# LoveOfUs 项目功能优化总结

## 一、项目概述

LoveOfUs 是一款情侣游玩照片存储与分享 Web 应用，基于 **Vue 3 + Spring Boot + FastAPI** 技术栈构建。本文档总结了项目的优化需求，涵盖前端、后端、AI层和部署等方面。

---

## 二、前端优化

### 2.1 安全问题优化

#### 2.1.1 localStorage 存储 Token（严重级别：CRITICAL）

**问题描述：** Token 存储在 localStorage 中，存在 XSS 攻击风险。

**修复建议：**
- 使用 sessionStorage 替代 localStorage（会话级存储）
- 实现 httpOnly Cookie 方案（推荐）
- 或使用内存存储（页面刷新后需重新登录）

#### 2.1.2 调试日志泄露敏感信息（严重级别：CRITICAL）

**问题描述：** 生产环境 console.log 会暴露用户认证状态。

**修复建议：**
- 使用环境变量控制日志输出
- 实现日志级别控制
- 构建时清理调试日志

### 2.2 性能优化

#### 2.2.1 图片加载优化

| 优化项 | 方案 | 说明 |
|--------|------|------|
| 懒加载 | 使用 `v-lazy` 指令 | 减少首屏加载时间 |
| WebP 格式 | 自动转换图片格式 | 减少文件大小 30-50% |
| CDN | 图片资源 CDN 加速 | 提升加载速度 |
| 多尺寸支持 | thumbnail/small/medium/original | 按场景加载合适尺寸 |

#### 2.2.2 路由懒加载

```typescript
// 所有页面组件使用动态导入
const Home = () => import('@/views/Home.vue')
const PhotoDetail = () => import('@/views/PhotoDetail.vue')
```

#### 2.2.3 虚拟列表

- 时间线大量照片时使用虚拟滚动（`vue-virtual-scroller`）
- 减少 DOM 节点数量，提升渲染性能

#### 2.2.4 缓存策略

- 使用 `keep-alive` 缓存首页状态
- SWR 策略更新数据
- 图片预加载（详情页预加载前后各 2 张照片）

### 2.3 移动端适配

| 策略 | 实现 | 说明 |
|------|------|------|
| rem 适配 | `postcss-pxtorem` + `amfe-flexible` | 基于 375px 设计稿 |
| 安全区域 | `env(safe-area-inset-bottom)` | 适配 iPhone X+ 底部黑条 |
| 触摸事件 | `@touchstart` / `@touchend` | 滑动切换、上拉加载 |
| 手势缩放 | `@pinch` / `@pan` | 图片查看双指缩放 |

## 三、后端优化

### 3.1 安全问题优化

#### 3.1.1 Token 刷新竞态条件（严重级别：HIGH）

**问题描述：** 多个并发请求可能同时触发 Token 刷新。

**修复建议：**
```typescript
// 使用单例模式确保只有一个刷新请求
let refreshPromise: Promise<boolean> | null = null

if (!refreshPromise) {
  refreshPromise = userStore.doRefreshToken().finally(() => { 
    refreshPromise = null 
  })
}
const ok = await refreshPromise
```

#### 3.1.2 密码哈希算法安全性不足（严重级别：HIGH）

**问题描述：** 使用纯 JavaScript 实现的 SHA-256，缺乏盐值。

**修复建议：**
- 使用 bcryptjs 替代自定义 SHA-256
- 后端使用 BCrypt 强哈希算法

#### 3.1.3 路由守卫逻辑缺陷（严重级别：HIGH）

**问题描述：** 获取用户信息失败时不清理 Token。

**修复建议：**
```typescript
// 区分网络错误和认证错误
if (error.response?.status === 401) {
  userStore.logout()
  return { name: 'Login' }
}
```

### 3.2 导出功能优化

#### 3.2.1 ZIP 压缩包导出

**当前状态：**
- ✅ 前端 UI 完整实现
- ✅ 前端 API 层已定义
- ❌ 后端 ExportController 未实现
- ❌ 后端 ExportService 未实现

**优化方案：**
1. 实现 ExportController 和 ExportService
2. 使用 JDK 内置 `java.util.zip` 无需额外依赖
3. 支持按日期分文件夹、包含照片元数据
4. 使用异步任务处理大文件导出

#### 3.2.2 PDF 相册导出

**当前状态：**
- ❌ 缺少 iText 依赖
- ❌ 后端逻辑未实现

**优化方案：**
1. 新增 iText 7 依赖
2. 实现多种布局模板（grid/timeline/story/collage）
3. 支持多套主题样式
4. 添加中文字体支持

#### 3.2.3 视频影集导出

**当前状态：**
- ❌ 缺少 JCodec 依赖
- ❌ 后端逻辑未实现

**优化方案：**
1. 新增 JCodec 依赖（纯 Java 实现）
2. 实现多种视频风格（simple/cinematic/romantic/vintage）
3. 支持转场效果和背景音乐
4. 添加智能排序算法

### 3.3 数据库优化

#### 3.3.1 新增导出记录表

```sql
CREATE TABLE export_record (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id INT NOT NULL,
    format VARCHAR(10) NOT NULL COMMENT 'zip/pdf/video',
    status VARCHAR(20) NOT NULL DEFAULT 'pending',
    file_path VARCHAR(500),
    file_size BIGINT,
    photo_count INT DEFAULT 0,
    options JSON,
    created_at DATETIME NOT NULL,
    completed_at DATETIME,
    FOREIGN KEY (user_id) REFERENCES user(id)
);
```

#### 3.3.2 缓存优化

- 缓存热门时间线数据
- Redis 缓存用户统计数据
- 图片缩略图缓存（7天有效期）

## 四、AI层优化

### 4.1 基础AI能力（阶段一）

#### 4.1.1 场景识别

- **模型：** CLIP ViT-L/14
- **功能：** Zero-shot 场景分类，支持 50+ 类别
- **部署：** ONNX/TensorRT

#### 4.1.2 标签生成

- **模型：** BLIP-2 / LLaVA
- **功能：** 多模态标签生成
- **类别：** 场景、对象、人物、情绪、活动、时间、季节

#### 4.1.3 人脸识别

- **模型：** InsightFace / FaceNet
- **功能：** 人脸检测、特征提取、聚类、验证
- **流程：** 检测 → 特征提取 → 向量化 → 聚类

#### 4.1.4 情绪分析

- **模型：** FER2013 训练模型
- **类别：** 开心、温馨、浪漫、搞怪、安静、兴奋

### 4.2 智能功能增强（阶段二）

#### 4.2.1 智能相册聚类

**多维度聚类策略：**
- 时间聚类：DBSCAN 基于时间密度
- 地点聚类：GPS 坐标 DBSCAN
- 人脸聚类：基于特征向量
- 场景聚类：标签相似度

#### 4.2.2 智能搜索功能

**多模态搜索架构：**
- 文本搜索：标签/描述匹配
- 图片搜索：特征提取 + 向量相似度
- 语义搜索：CLIP 编码 + 向量检索
- 混合搜索：多路召回 + 重排序

#### 4.2.3 智能推荐系统

**推荐场景：**
1. 每日回忆："历史上的今天"照片推荐
2. 精选时刻：基于质量评分的最佳照片
3. 相似照片清理：检测并推荐删除重复/相似照片
4. 相册补全：基于聚类结果推荐遗漏照片

### 4.3 高级创意功能（阶段三）

#### 4.3.1 AI回忆视频生成

**视频生成流水线：**
1. 智能照片精选
2. 智能排序（时间线/故事线）
3. 动态效果生成（Ken Burns 效果）
4. 转场效果选择
5. 背景音乐匹配
6. 字幕生成
7. 视频合成

#### 4.3.2 AI照片修复与增强

**功能列表：**
1. 老照片修复：去划痕、上色、清晰度提升
2. 人像增强：美颜、肤色优化、背景虚化
3. 超分辨率：低分辨率图片放大
4. 风格迁移：照片转油画/水彩/素描

#### 4.3.3 AI文案生成

**应用场景：**
1. 照片描述生成：自动为照片生成诗意描述
2. 相册标题生成：基于照片内容生成相册名称
3. 纪念日文案：特殊日期自动生成祝福文案
4. 社交媒体文案：一键生成分享文案

## 五、部署优化

### 5.1 Nginx 配置优化

| 优化项 | 方案 | 说明 |
|--------|------|------|
| Worker 进程 | `worker_processes auto` | 自动匹配 CPU 核心数 |
| 静态资源缓存 | 30天缓存 + CDN | 减少 Nginx 负载 |
| 图片缓存 | `proxy_cache` 7天有效 | 缩略图走缓存 |
| Gzip 压缩 | 启用 Gzip | 减少传输大小 |
| SSL 会话复用 | SSL Session Cache | 减少 SSL 握手开销 |

### 5.2 Docker Compose 优化

**服务配置：**
- MySQL：健康检查 + 数据持久化
- Redis：密码认证 + AOF 持久化
- MinIO：对象存储集群
- Spring Boot：生产环境配置
- FastAPI：GPU 资源预留
- Vue 前端：多实例负载均衡

### 5.3 性能监控

| 工具 | 用途 |
|------|------|
| ELK / Loki | 日志集中管理 |
| Prometheus + Grafana | 性能监控 |
| Sentry | 前端错误追踪 |
| Spring Boot Actuator | 后端健康检查 |
| Nginx Amplify | Nginx 性能监控 |

### 5.4 数据库初始化

**核心表结构：**
- 用户表 `user`：基本信息、绑定关系
- 照片表 `photo`：照片元数据、AI 分析结果
- 相册表 `album`：相册信息
- 照片-相册关联表 `photo_album`
- 标签表 `tag`：手动/AI 标签
- 照片-标签关联表 `photo_tag`
- 导出记录表 `export_record`

## 七、总结

本项目功能优化涵盖前端、后端、AI层和部署四个方面：

1. **前端**：重点解决安全问题，提升性能和移动端体验
2. **后端**：完善导出功能，优化安全机制和数据库性能
3. **AI层**：分阶段实施，从基础AI能力到高级创意功能
4. **部署**：优化 Nginx、Docker Compose 和监控体系

建议按照优先级逐步实施，确保项目安全性和功能完整性。
