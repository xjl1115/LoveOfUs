# LoveOfUs 后端用户体验优化建议

**基于项目文件综合分析**  
**日期：** 2026-06-25

---

## 一、认证与登录体验

### 1.1 登录失败次数限制（高优先级）

**当前状态：** 登录接口未做失败次数限制。

**优化方案：**
- 使用 Redis 记录连续登录失败次数（5次阈值）
- 超过阈值后锁定账号 30 分钟
- 返回友好提示，告知用户锁定时间
- 提供账号解锁途径（等待或联系客服）

### 1.2 Token 刷新优化（高优先级）

**当前状态：** Token 过期后直接跳转登录页，用户体验中断。

**优化方案：**
- 实现双 Token 策略：Access Token（24小时）+ Refresh Token（30天）
- 前端拦截器在 Token 即将过期时静默刷新
- 对 Refresh Token 也设置过期时间和黑名单机制
- 避免用户感知 Token 过期，实现无感续期

### 1.3 密码复杂度校验（中优先级）

**当前状态：** 密码仅要求长度 ≥ 6 位。

**优化方案：**
- 注册/重置密码时要求包含大小写字母 + 数字
- 前端实时提示密码强度
- 后端校验并返回明确的错误提示

### 1.4 敏感操作二次验证（中优先级）

**当前状态：** 修改密码、注销账号等操作仅需一次验证。

**优化方案：**
- 修改密码、注销账号、解绑伴侣等敏感操作需验证码二次确认
- 发送验证码到绑定手机/邮箱
- 验证通过后方可执行操作

## 二、照片管理体验

### 2.1 照片压缩与多尺寸生成（高优先级）

**当前状态：** 已有基础的缩略图生成逻辑。

**优化方案：**
- 上传时自动生成 4 种尺寸：thumbnail（200px）、small（600px）、medium（1200px）、original（原图）
- 前端根据场景加载合适尺寸，减少流量消耗
- 支持 WebP 格式自动转换，减少文件大小 30-50%

### 2.2 EXIF 信息自动提取（高优先级）

**当前状态：** 需手动填写拍摄时间、地点等信息。

**优化方案：**
- 上传时自动解析 EXIF 数据（拍摄时间、GPS 坐标、设备信息）
- 自动填充拍摄时间、地点名称、城市、省份
- 用户可手动修改自动提取的信息

### 2.3 照片去重（中优先级）

**当前状态：** 无重复照片检测机制。

**优化方案：**
- 基于文件 MD5 检测完全相同的重复照片
- 上传时提示用户是否存在重复
- 支持批量清理重复照片

### 2.4 批量操作优化（低优先级）

**当前状态：** 批量删除使用单条删除语句。

**优化方案：**
- 批量删除使用 `IN` 语句，减少数据库查询次数
- 批量添加照片到相册使用事务保证原子性
- 大批量操作提供进度反馈

## 三、相册管理体验

### 3.1 相册封面自动更新（高优先级）

**当前状态：** 删除封面照片后相册无封面。

**优化方案：**
- 删除封面照片时自动更新为相册内最新照片
- 添加照片到空相册时自动设为封面
- 移除所有照片后封面置为 null

### 3.2 相册拖拽排序（中优先级）

**当前状态：** 相册按创建时间排序，无法自定义。

**优化方案：**
- 后端支持 `sort_order` 字段排序
- 提供批量更新排序接口
- 前端实现拖拽交互

### 3.3 AI 智能相册（中优先级）

**当前状态：** 已有基础 AI 标签功能。

**优化方案：**
- 基于时间聚类自动创建"某次旅行"相册
- 基于地点聚类自动创建"某城市"相册
- 基于场景聚类自动创建"美食"、"风景"等相册
- 用户可手动调整自动生成的相册

### 3.4 相册分享（低优先级）

**当前状态：** 无相册分享功能。

**优化方案：**
- 生成带有效期的分享链接
- 支持设置访问密码
- 分享页面仅展示照片，不可操作

## 四、导出功能体验

### 4.1 视频影集导出（高优先级）

**当前状态：** 仅支持 ZIP 和 PDF 导出。

**优化方案：**
- 新增 MP4 视频影集导出
- 支持多种风格（简约、电影、浪漫）
- 支持背景音乐和转场效果
- 使用 JCodec（纯 Java 实现）减少依赖

### 4.2 导出进度实时推送（中优先级）

**当前状态：** 导出状态需轮询查询。

**优化方案：**
- 使用 SSE（Server-Sent Events）实时推送导出进度
- 前端展示进度条和预估剩余时间
- 支持导出任务取消

### 4.3 导出文件缓存（中优先级）

**当前状态：** 相同照片组合每次导出都重新生成。

**优化方案：**
- 基于照片 ID 组合生成缓存 Key
- 相同组合直接返回缓存文件
- 缓存文件设置有效期（如 7 天）

### 4.4 导出任务限流（低优先级）

**当前状态：** 无导出任务数量限制。

**优化方案：**
- 限制每个用户同时进行的导出任务数（如最多 3 个）
- 队列化处理，超出限制的任务排队等待
- 返回任务排队位置和预估等待时间

## 五、用户信息体验

### 5.1 敏感信息脱敏（高优先级）

**当前状态：** 接口可能返回完整手机号、邮箱。

**优化方案：**
- 手机号脱敏：`138****8000`
- 邮箱脱敏：`lo***@example.com`
- 密码哈希不返回给前端
- 在 VO 层统一处理脱敏逻辑

### 5.2 操作日志审计（中优先级）

**当前状态：** 无操作日志记录。

**优化方案：**
- 记录关键操作：登录、修改信息、注销、删除照片/相册
- 记录操作时间、IP、设备信息
- 支持管理员查询操作日志
- 定期归档日志数据

### 5.3 用户数据导出（中优先级）

**当前状态：** 无个人数据导出功能。

**优化方案：**
- 支持导出个人数据（JSON/CSV 格式）
- 包含照片列表、相册列表、纪念日等
- 上传到对象存储，返回下载链接
- 符合 GDPR 数据可携带权要求

### 5.4 账号注销优化（低优先级）

**当前状态：** 注销为同步操作，大量数据时耗时较长。

**优化方案：**
- 注销任务异步处理
- 返回预估处理时间
- 完成后通过邮件/短信通知用户
- 清理数据时使用批量删除优化性能

## 六、性能优化体验

### 6.1 数据库查询优化（高优先级）

**当前状态：** 部分查询未使用覆盖索引。

**优化方案：**
- `photo` 表增加联合索引 `(user_id, taken_date, is_deleted)`
- `photo_album` 表增加联合索引 `(album_id, photo_id)`
- 避免 `SELECT *`，只查询必要字段
- 使用覆盖索引减少回表查询

### 6.2 缓存策略优化（中优先级）

**当前状态：** 已有基础 Redis 缓存。

**优化方案：**
- 缓存预热：系统启动时预加载热门数据
- 缓存穿透防护：使用空值缓存或布隆过滤器
- 缓存雪崩防护：过期时间增加随机值
- 缓存击穿防护：使用互斥锁或永不过期策略

### 6.3 异步任务优化（中优先级）

**当前状态：** 已配置多个线程池。

**优化方案：**
- 监控线程池使用率、队列积压
- 设置任务超时时间，防止长时间阻塞
- 失败任务自动重试（最多 3 次）
- 支持用户取消正在执行的任务

### 6.4 SSE 连接优化（低优先级）

**当前状态：** SSE 超时 30 分钟。

**优化方案：**
- 增加心跳机制，每 30 秒发送心跳包
- 防止中间件（Nginx）提前断开连接
- 确保 `proxy_buffering off` 配置生效

## 七、安全体验优化

### 7.1 Token 黑名单清理（高优先级）

**当前状态：** Token 黑名单未设置过期时间。

**优化方案：**
- 黑名单 Key 设置 TTL，与原 Token 剩余有效期一致
- 定期清理过期黑名单
- 减少 Redis 内存占用

### 7.2 数据归属校验（高优先级）

**当前状态：** 多数接口通过 JWT 获取 userId，但未显式校验资源归属。

**优化方案：**
- Service 层增加数据归属校验
- 查询纪念日详情时校验是否属于当前用户或伴侣
- 防止 IDOR（越权访问）漏洞

### 7.3 接口响应脱敏（中优先级）

**当前状态：** 部分接口可能返回敏感字段。

**优化方案：**
- 统一在 VO 层处理字段脱敏
- 密码哈希、绑定码等敏感信息不返回
- 文件上传接口返回文件 URL 而非存储路径

### 7.4 文件上传安全（中优先级）

**当前状态：** 文件上传有基础校验。

**优化方案：**
- 严格限制上传文件 MIME 类型白名单
- 上传文件大小限制（照片 ≤ 20MB，头像 ≤ 5MB）
- 上传后进行病毒扫描（可选）

## 八、代码质量体验

### 8.1 异常处理统一（高优先级）

**当前状态：** `SecurityConfig` 中存在无效代码。

**优化方案：**
- 删除无效的 `ObjectMapper` 调用
- 统一异常响应格式
- 避免重复创建 `ObjectMapper` 实例

### 8.2 常量管理（中优先级）

**当前状态：** 部分硬编码值分散在业务代码中。

**优化方案：**
- Redis Key 前缀统一到常量类
- Token 过期时间、分页默认值等集中管理
- 避免魔法值和重复字符串

### 8.3 日志规范（中优先级）

**当前状态：** 日志语言不统一，部分打印中文。

**优化方案：**
- 统一日志语言（建议英文）
- 关键操作记录审计日志
- 避免在日志中打印敏感信息（Token、密码、验证码）

### 8.4 方法复杂度控制（低优先级）

**当前状态：** 部分 Service 方法超过 80 行。

**优化方案：**
- 拆分为多个职责单一的小方法
- 使用策略模式处理不同导出格式（ZIP/PDF/Video）
- 提升代码可读性和可维护性

---

## 九、运维监控体验

### 9.1 健康检查（高优先级）

**当前状态：** 未确认是否引入 Spring Boot Actuator。

**优化方案：**
- 引入 `spring-boot-starter-actuator`
- 暴露健康端点 `/actuator/health`
- 配置 MySQL、Redis、MinIO 等依赖组件的健康检查

### 9.2 异步任务监控（中优先级）

**当前状态：** 已配置多个线程池，但无监控。

**优化方案：**
- 暴露线程池活跃度、队列大小等指标
- 对任务执行时间做监控和告警
- 集成 Prometheus + Grafana 可视化

### 9.3 Nginx 日志优化（低优先级）

**当前状态：** Nginx 已配置 access_log。

**优化方案：**
- 启用访问日志按天切割
- 对静态资源增加细粒度缓存策略
- 监控 Nginx 后端节点健康状态
