# LoveOfUs 前端用户体验优化建议

**基于项目文件综合分析**  
**日期：** 2026-06-25

---

## 一、安全体验优化

### 1.1 Token 存储方式（高优先级）

**当前状态：** Token 存储在 localStorage 中，存在 XSS 攻击风险。

**优化方案：**
- 使用 `sessionStorage` 替代 `localStorage`（会话级存储）
- 实现 httpOnly Cookie 方案（推荐，安全性最高）
- 若使用 Cookie，需配置 `SameSite=Strict` 和 `Secure` 属性
- 避免将 Token 持久化在 localStorage 中，降低 XSS 攻击后的横向移动风险

### 1.2 Token 过期判断时机（高优先级）

**当前状态：** 请求拦截器中判断 Token 是否过期，若过期直接跳转登录页。

**优化方案：**
- 区分"已过期"和"即将过期"两种情况
- 即将过期（如 5 分钟内）的 Token 优先触发静默刷新
- 已过期的 Token 才跳转登录页
- 实现单例模式避免多个并发请求同时触发刷新

### 1.3 生产环境日志输出（高优先级）

**当前状态：** 路由守卫中仍存在 `logger.debug` 等日志输出。

**优化方案：**
- 生产环境完全禁用 console 输出
- 使用环境变量统一控制日志级别
- 接入 Sentry 等错误上报平台替代 console 日志
- 构建时清理调试日志

### 1.4 路由守卫逻辑缺陷（高优先级）

**当前状态：** 获取用户信息失败时不清理 Token。

**优化方案：**
- 区分网络错误和认证错误（401 状态码）
- 401 错误时清理 Token 并跳转登录页
- 网络错误时保留 Token，仅提示用户

```typescript
if (error.response?.status === 401) {
  userStore.logout()
  return { name: 'Login' }
}
```

## 二、性能优化体验

### 2.1 图片懒加载（高优先级）

**当前状态：** 已存在 `v-lazy` 自定义指令，但未全局应用。

**优化方案：**
- 在时间线、相册详情、足迹地图等照片密集场景统一启用懒加载
- 对首屏可见图片做 `preload` 或 `prefetch`
- 使用 Intersection Observer API 实现懒加载
- 支持 WebP 格式自动转换，减少文件大小 30-50%

### 2.2 虚拟滚动（高优先级）

**当前状态：** 已存在 `VirtualPhotoList.vue` 组件，但未确认是否被全面使用。

**优化方案：**
- 对时间线、搜索结果等长列表统一使用虚拟滚动
- 减少 DOM 节点数量，提升渲染性能
- 使用 `vue-virtual-scroller` 或 `@tanstack/vue-virtual`
- 提前 2 屏预加载照片

### 2.3 路由懒加载（中优先级）

**当前状态：** 路由已使用动态导入。

**优化方案：**
- 确保所有页面组件使用 `() => import()` 动态导入
- 对大型依赖（如 echarts、qrcode）使用动态导入
- 避免在应用启动时一次性加载所有依赖
- 开启 `rollup-plugin-visualizer` 分析产物体积

### 2.4 keep-alive 缓存（中优先级）

**当前状态：** 未在路由中配置 `keep-alive`。

**优化方案：**
- 对首页、相册列表等用户频繁往返的页面启用 `keep-alive`
- 减少重复请求和数据重渲染
- 使用 SWR 策略更新缓存数据
- 注意内存占用，避免缓存过多页面

### 2.5 图片压缩（中优先级）

**当前状态：** 未确认是否有客户端压缩逻辑。

**优化方案：**
- 上传前在客户端进行图片压缩（使用 `compressorjs`）
- 大图超过 1920px 自动缩放宽边
- 减少带宽消耗和服务器压力
- 压缩质量可配置（默认 80%）

### 2.6 图片预加载（中优先级）

**当前状态：** 未确认是否有预加载逻辑。

**优化方案：**
- 进入详情页时预加载前后各 2 张照片
- 首页加载完成后，空闲时预取相册页和上传页资源
- 使用 `<link rel="prefetch">` 或动态创建 Image 对象

### 2.7 构建产物体积优化（低优先级）

**当前状态：** echarts 打包后超过 1MB。

**优化方案：**
- 使用 CDN 加载 echarts、vue、vant 等库
- 对非首屏依赖做动态分割
- 开启 gzip 压缩
- 使用 Tree Shaking 移除未使用代码

## 三、组件架构优化

### 3.1 单文件组件拆分（高优先级）

**当前状态：** `Profile.vue` 超过 700 行，包含多个功能模块。

**优化方案：**
- 将纪念日管理、通知设置、绑定码管理等拆分为独立子组件
- 提升代码可读性和复用性
- 降低单文件维护成本
- 建议组件拆分粒度：每个组件不超过 300 行

### 3.2 API 层类型定义（中优先级）

**当前状态：** 部分 API 文件直接内联定义请求参数类型。

**优化方案：**
- 将所有 DTO/VO 类型统一放置在 `src/types` 目录下
- 避免在 API 层与组件层重复定义类型
- 使用 TypeScript 接口定义请求和响应类型
- 建立类型文档，方便前后端协作

### 3.3 状态管理拆分（中优先级）

**当前状态：** 所有用户相关状态集中在 `userStore` 中。

**优化方案：**
- 将认证状态（Token、refreshToken）与业务状态（userInfo、daysTogether）拆分到不同 Store
- 便于模块化和测试
- 减少 Store 之间的耦合
- 建议拆分：`authStore`、`userStore`、`photoStore`、`albumStore`

### 3.4 公共组件完善（中优先级）

**当前状态：** 已定义公共组件列表，但部分组件可能未实现。

**优化方案：**
- 完善 `EmptyState` 空状态占位组件
- 完善 `LoadingSkeleton` 骨架屏加载组件
- 完善 `UploadProgress` 上传进度条组件
- 完善 `ExportProgress` 导出进度条组件
- 统一组件 API 设计，保持一致性

## 四、交互体验优化

### 4.1 请求错误提示（中优先级）

**当前状态：** 响应拦截器中所有非 200 响应统一调用 `showToast`。

**优化方案：**
- 对 401、403、500 等错误做差异化提示
- 401：跳转登录页，提示"登录已过期"
- 403：提示"无权限访问"
- 422：提示具体校验错误信息
- 429：提示"请求过于频繁，请稍后再试"
- 对并发请求导致的重复 Toast 进行去重或队列控制

### 4.2 加载状态管理（中优先级）

**当前状态：** 部分页面使用独立的 `loading` 变量管理加载状态。

**优化方案：**
- 引入全局 Loading 状态管理
- 避免重复实现加载状态逻辑
- 对长时间操作（导出、批量上传）提供进度提示
- 使用骨架屏提升加载体验

### 4.3 表单校验统一（中优先级）

**当前状态：** 纪念日、绑定码等表单校验逻辑分散在组件中。

**优化方案：**
- 使用 VeeValidate 或自定义 composable 统一表单校验规则
- 抽离通用校验函数（手机号、日期、必填等）
- 提供实时校验反馈
- 统一错误提示样式

### 4.4 下拉刷新与无限滚动（低优先级）

**当前状态：** 未确认是否已实现。

**优化方案：**
- 首页时间线下拉刷新最新照片
- 上拉无限滚动加载更多
- 使用 Vant 的 `van-pull-refresh` 和 `van-list` 组件
- 添加加载中/没有更多等状态提示
